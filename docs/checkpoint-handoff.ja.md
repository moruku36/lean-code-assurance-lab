# 実行モードと言語をまたぐカーソルの引き継ぎ

[English](checkpoint-handoff.md) · [一括走査の仕様](checkpoint-walk.ja.md)

一括走査はファイルのダイジェストと各ページの境界キーを別に返します。受け手は `[ダイジェスト, 境界キー]` を作り、必要ならページサイズを変えて再開できます。**境界キーは数値に変換せず、十進文字列のまま渡します。** ダイジェストで確認できるのはファイルの版だけです。同じ版に存在する別のキーなら、その位置から再開します。

- 2^53、2^64、127桁・128桁の境界を含む合成データで、PythonとTypeScriptの両方向、1ページと一括の両方向の組み合わせを **40件** 確認。保持した先頭部分と再開後の残りをつなぐと、削除済みの行を含めすべて独立した期待値と一致しました。一括走査が返す全結果のうち、クライアントが先頭ページだけ保持した想定であり、ストリーミングの中断ではありません。
- 意図的にJavaScriptの `Number` を経由させると、境界キー `9007199254740993` が、同じ版内に存在する直前の `9007199254740992` に丸まりました。両言語・両モードとも受理し、読了済みの `9007199254740993` を再び返しました。正しいカーソルでの挙動は一致しているため、クライアント側の変換で起きる重複です。指数表記に丸めた別の巨大キーと129桁の境界キーは拒否されました。
- 同一バイト列への置き換えなら再開でき、版番号を一つ変更したファイルに対しては、元のカーソルでの再開を4通りとも拒否。差し替えは呼び出し間に行い、同時書き込みは未検証です。
- Leanで、正確な境界なら前半と残りをつなぐと元の列に戻ること、直前のキーを渡すと読了済みの境界行が再出現することを証明。実行モデルも10件で一致。実際の丸めやファイル・実装を証明したわけではなく、今回の問題は通常テストでも確認できました。
