# 1回の読み込みでチェックポイントを走査する

[English](checkpoint-walk.md) · [1ページ版の仕様](checkpoint-page.ja.md)

## 検証したいこと

ページごとにファイル全体を読み直さず、同じ行とカーソルを返せるかを合成データで確認しました。起点はローカル版 `9ba3ede95ff23dd15bf9b406b42eeb8a28883dd7`。従来の1ページモードは変更せず、走査時の版を固定してよい場合だけ明示的に `--walk` を使います。 比較元のスクリプトは[ベースライン](../examples/checkpoint_page/baseline/)に同梱しているため、元のローカルコミット履歴なしで再現できます。

```sh
printf '%s' '[null,"37"]' | python3 -B examples/checkpoint_page/page.py sample.jsonl --walk
printf '%s' '[null,"37"]' | node examples/checkpoint_page/page.ts sample.jsonl --walk
```

入力は昇順で一意のキー、最大128桁の十進文字列のキー・版番号、最大256 KiBの正規形式JSON Linesです。`--walk` は一度開いたファイルを末尾まで検証し、取得したバイト列のSHA-256を付けて `["ok", ダイジェスト, [[ページの行, 次の境界キーまたはnull], ...]]` を返します。非nullのキーはダイジェストと組み合わせて従来のカーソルとして使えます。最後はnullで、空・読了時は空の終端ページを1件返します。開始カーソルが指す内容と現在のバイト列が違えば拒否します。同じ内容に置き換えた場合は再開できます。末尾が不正なら途中までの結果も返しません。入力と結果をメモリに保持するので、無制限のストリーミングには使いません。

## 結果

- PythonとTypeScriptの実際のコマンドがそれぞれ **54走査** で、行番号を使う独立した期待値と一致。巨大整数の隣接キー、削除済みの行、読了済みカーソルを含みます。別途 **54件ずつ**、従来モードが旧版と同じ応答を返しました。
- **1,000行・254,000バイトの合成ファイル**を37行ずつ読み、従来版のPythonとTypeScriptを交互に実行した28ページと、両方の一括走査が一致しました。Linuxで対象ファイルを開いた回数は **28回 → 各1回**、検証したバイト列の延べ量は **7,112,000 → 254,000バイト**でした。物理I/Oや処理時間を計測した結果ではありません。
- 版を照合しない改変版は別の版を返し、読み進め方を1行ずらす改変版は `18446744073709551616` を飛ばしました。どちらも通常テストで検出。Lean 4.19.0の定理4件を検査し、実行モデルも54走査で一致しました。この例でLeanだけが見つけた不具合はありません。

Leanが検証するのは、型付きの版が変われば拒否し、正のページサイズで走査結果をつなぐと正しい順番の残り全行になることです。実装・ハッシュ・ファイルシステムを証明したわけではありません。ファイルの差し替えはプロセス間で行い、走査中の鮮度や上書き競合、過去版の保持、障害復旧、他環境の性能は未検証です。ページ間の変更も検出したい用途は従来モードのままにします。
