# 大きな整数キーでチェックポイントをページ分割する

[English](checkpoint-page.md) · [研究計画](experiments.ja.md)

## 何を確かめるか

ファイル全体を原子的に置き換えても、1ページ目と2ページ目で別の版を読めます。そこで、続きのキーと一緒に読み取ったファイルのSHA-256を渡し、内容が変わっていれば `checkpoint-changed` を返す合成例を作りました。このエラーが出たら、取得途中のページを破棄して先頭から読み直します。別の版のページは連結しません。

保存形式は改行区切りの正準JSONで、行は「キー、版番号、更新 `U` または削除記録 `D`」です。キーは重複なしで数値の昇順。キーと版番号は最大128桁の十進文字列で受け取り、Pythonは `int`、TypeScriptは `bigint` で比較します。空ファイルは空のチェックポイントです。全体の上限は256 KiBで、削除記録もページに含まれます。

CLIにはファイルパスと `[カーソル, "件数"]` を渡します。最初のカーソルは `null`、件数は1〜100の文字列。成功時は `["ok",ファイルのSHA-256,取得行,次のカーソル]` を返します。次のカーソルが `null` なら最後です。

## 再現と結果

Lean 4.19.0、Python 3.10以上、Node.js 24以上を用意し、リポジトリのルートで実行します。

```sh
python3 -B scripts/check_checkpoint_page.py --without-lean
LEAN=/absolute/path/to/lean python3 -B scripts/check_checkpoint_page.py
```

[計測したJSON](../evidence/checkpoint-page.json) · [Leanモデル](../CheckpointPage.lean) · [2言語のCLI](../examples/checkpoint_page/)

- Python・TypeScriptの実CLIは、独立した行位置オラクルと **各54件** で一致。両言語を別プロセスで交互に起動して最終ページまで読む **12通り** も一致。不正な要求10件、壊れた／存在しないチェックポイント15件を各々拒否し、空のファイルは受理。
- 続きの比較だけを JavaScript の `Number` に変えると **6件** 不一致。具体的には `9007199254740992` の次にある `9007199254740993` を飛ばします。ファイルの版を確認しない対照は、更新後のページを混ぜ、読んだ境界より前に追加されたキーを見落としました。両CLIは古いカーソルを拒否し、同じバイト列への置き換えでは再開できます。
- Leanは、型付きのレコード列が異なる場合の拒否と、数値が厳密な昇順の列で正しい後続を返すことを検査しました。モデルの実行も同じ54件で一致。**今回の意図的な不具合は通常テストでもすべて検出でき、Leanだけで増えた検出はありません。** 未見データに対するエージェント比較ではありません。

Leanが使う版の同一性は型付きの行列そのものの等しさです。SHA-256やJSONパーサー、OSを証明したわけではありません。実行試験はLinuxの別プロセスを使い、ページ間で同じディレクトリ内のファイルを置き換えています。同時書き込み、電源断、分散ストレージ、Windows、性能は未検証。毎回全体を読みハッシュするため、本番採用の提案ではありません。TypeScriptはNode.jsの型除去で実行し、別途 `tsc` は使っていません。
